# Diagnose an interrupted transfer

Distinguish preparation failure from an interrupted browser save before choosing recovery.

## Prerequisites

- Archive remote download and transfer-edit permission must be enabled.
- You must be able to open the relevant transfer record in Transfers.

## Steps

### 1. Inspect the transfer

Open Transfers, find the affected record using Search transfer history, and expand its summary. Record its mode, status, progress, artifact readiness and displayed error.

**Expected:** Transfer details expose the reported error and file status. Preparation and downloaded byte counts are shown separately.

### 2. Choose the supported recovery

For failed, cancelled, interrupted or expired remote preparation, resolve the displayed cause and use Prepare again. For a partial browser save, use Resume save when offered. If Source version required is displayed, start a new transfer with the producer's full size and SHA-256 as instructed.

**Expected:** Preparation and save controls match the reported condition. A source-version error is not treated as a resumable completed source.

### 3. Verify recovery

Wait for the prepared artifact to be ready, choose a save location, and verify that the save finishes. If the error remains, retain the record and seek support with the transfer identifier and sanitized error.

**Expected:** A ready artifact and completed local save are separate checks. An unresolved error remains a support case.

## Expected result

- Recovery uses the control for the observed failure stage; a prepared artifact alone does not establish a completed device download.

## Recovery

- For missing derivatives, generate the missing proxy type only when that action is offered and you have processing permission. Reinspect the transfer before preparing again.
- Do not remove a failed record before preserving the identifier and sanitized error for support.
